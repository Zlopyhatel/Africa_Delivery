# Дипломный проект: Комплексное архитектурное решение для платформы Africa Delivery

Настоящий репозиторий содержит полный пакет проектной, технической и финансово-экономической документации для мультикатегорийного маркетплейса Africa Delivery. Проектирование выполнено на основе жестких ограничений стартапа (8 недель разработки, запуск 15 октября, регулярный ИТ-бюджет \$5 000 в месяц, команда из 6 инженеров-контракторов) в соответствии с мультинациональными требованиями комплаенса (NDPR, KICA, POPIA).

---

## Полная структура репозитория и реестр артефактов (Чек-лист проекта)

### 📂 Директория `Task1/` — Контекст, стейкхолдеры и противоречия
* `stakeholder-matrix.md` — Матрица стейкхолдеров, включающая визуальную диаграмму «Влияние / интерес» (синтаксис Mermaid/PlantUML).
* `architecture-canvas.md` — Заполненный архитектурный канвас проекта, структурированный по целевым бизнес- и техническим секциям.
* `contradictions.md` — Реестр архитектурно-бизнесовых противоречий (минимум 5 строк с указанием конфликтующих сторон, рисков и рекомендаций).
* `open-questions.md` — Таблица открытых вопросов к стейкхолдерам с фиксацией блокирующих факторов, дедлайнов и консервативных допущений.

### 📂 Директория `Task2/` — Базовые архитектурные чертежи, TCO и манифест
* `options-comparison.md` — Сравнительный анализ архитектурных стилей (Монолит vs Микросервисы) на основе числовых критериев с итоговым выводом.
* `tco-model.xlsx` — Пятилетняя финансовая модель совокупной стоимости владения системой с изолированными листами под каждый сценарий.
* `adr-001-architecture-style.md` — Архитектурное решение №1 (ADR) по выбору компонентного модульного монолита на Go на основе расчетов TCO.
* `c4-context.puml` / `c4-context.png` — Контекстная диаграмма C4 (C4-PlantUML) с обязательными подписями всех интеграционных связей.
* `use-cases.puml` / `use-cases.png` — Диаграмма прецедентов (PlantUML) по ключевым сценариям MVP (визуальный контур приложения vs текстовый USSD).
* `architecture-vision.md` — Манифест архитектурного видения, сводящий воедино ИТ-стратегию и цели инвестора (по структуре приложения Б).
* `nairobi-slide.pptx` (или `.pdf`) — Презентация из одного аналитического слайда для встречи Совета директоров в Найроби.
* `nairobi-script.md` — Текстовый транскрипт речи перед инвесторами (1200–1500 слов, рассчитанный на 10 минут выступления).

### 📂 Директория `Task3/` — Нефункциональные требования (NFR) и отказоустойчивость
* `nfr-registry.md` — Реестр нефункциональных требований с метриками, способами проверки и экономическим обоснованием стоимости «девяток».
* `slo/catalog.md` — OpenSLO-контракт уровня обслуживания для автономного модуля каталога товаров (SLI, SLO, SLA).
* `slo/payments.md` — OpenSLO-контракт для модуля платежей, учитывающий финтех-ограничения африканских провайдеров (SLI, SLO, SLA).
* `slo/notifications.md` — OpenSLO-контракт для модуля SMS/WhatsApp уведомлений и шлюзов связи (SLI, SLO, SLA).
* `quality-attribute-scenarios.md` — Сценарии атрибутов качества (минимум 5 сценариев по 6 обязательных полей в каждом по приложению В).
* `fmea.md` — Анализ видов и последствия отказов (FMEA, минимум 5 строк) с расчетом индексов RPN для внутренних и партнерских контуров.
* `adr-002-caching-strategy.md` — Архитектурное решение №2 (ADR) по многоуровневой стратегии кэширования (CDN Edge + In-Memory Cache-Aside).
* `observability.md` — Стратегия наблюдаемости по 4 золотым сигналам, включающая инструменты и архитектурную схему сбора телеметрии.

### 📂 Директория `Task4/` — Топология размещения данных, комплаенс и файловер
* `data-residency-map.md` — Карта размещения данных по категориям и странам субъектов в соответствии с NDPR, KICA и POPIA.
* `cloud-regions-comparison.md` — Сравнительный анализ облачных регионов AWS, GCP, Azure и локальной инфраструктуры по SLA, ценам и Latency.
* `adr-003-data-residency.md` — Архитектурное решение №3 (ADR) по LUKS-шифрованию, управлению ключами AWS KMS и обратимости решений.
* `c4-container.puml` / `c4-container.png` — Детальная диаграмма контейнеров C4 с группировкой компонентов по географическим регионам развертывания.
* `deployment-diagram.puml` / `deployment-diagram.png` — Физическая схема развертывания серверов, VPN-туннелей и межсетевых экранов (PlantUML).
* `failover-plan.md` — Текстовый план отказоустойчивости и аварийного переключения при отказе центрального региона (сценарии, шаги, RTO/RPO).

### 📂 Директория `Task5/` — Бизнес-архитектура, дорожная карта и риски
* `capability-map.md` — Двухуровневая карта бизнес-возможностей (L1/L2) со стоимостной оценкой, рисками и решениями Build/Buy/Partner.
* `value-stream.puml` / `value-stream.png` — Диаграмма сквозного потока ценности (Value Stream) с нанесенными бизнес-возможностями (Capabilities).
* `services-per-capability.md` — Матрица соответствия возможностей конкретным программным сервисам с закреплением владельцев (Owners).
* `roadmap.md` — Технологическая дорожная карта на 12 месяцев со встроенным Agile-графиком спринтов в формате диаграммы **Mermaid Gantt**.
* `adr-004-payment-provider.md` — Архитектурное решение №4 (ADR) по финтех-интеграции шлюзов с фиксацией средней комиссии ≤ 2.5% GMV.
* `transition-architecture.md` — Архитектура переходных состояний системы по модели эволюционной трансформации «Сейчас ➔ MVP ➔ 12 месяцев».
* `risk-register.md` — Корпоративный реестр рисков стартапа с указанием вероятности, влияния, триггеров активации и стратегий митигации.
