# OpenSLO Service Contract: Сервис платежных операций (Payment Service)

## 1. Описание сервиса
Модуль отвечает за обработку платежей, интеграцию с внешними шлюзами (Paystack, Flutterwave, M-Pesa) и автоматизированный расчет с продавцами.

## 2. Индикатор уровня обслуживания (SLI)
* **Что измеряется:** Доступность внутренней платежной логики платформы (исключая внутренние сбои на стороне самих агрегаторов).
* **Формула расчета:** 
  $$\text{SLI} = \frac{\text{Количество успешных инициализаций сессий оплаты (HTTP 200/201)}}{\text{Общее количество попыток создания платежной сессии покупателями}} \times 100\%$$
* **Окно измерения:** Скользящее окно за 5 минут.
* **Источник данных:** Транзакционные логи Payment Gateway Adapter приложения Africa Delivery Core.

## 3. Целевой показатель (SLO)
* **Сквозное целевое значение процесса (End-to-End SLO):** **99.0%** успешных транзакций в течение календарного месяца. Этот показатель является жестко связанным (последовательное соединение) и напрямую ограничен базовой доступностью внешних африканских платежных провайдеров (Paystack, Flutterwave, M-Pesa), чей юридический SLA не превышает 99.0%.
* **Внутренний целевой показатель (Internal SLO):** **99.9%** успешных ответов для собственного программного кода платежного модуля (Payment Gateway Adapter) на Go.
* **Допустимый бюджет ошибок (Error Budget):** 1.0% неуспешных транзакций в месяц от общего объема платежных сессий покупателей. Из них 0.9% резервируется под операционные сбои на стороне внешних банков-эмитентов и сотовых вышек (STK Push таймауты), и только 0.1% — под внутренние технические сбои нашего монолита.

## 4. Гарантии бизнеса (SLA)
* **Что гарантируется клиенту:** Прием оплаты и проведение клиринга продавцам «день в день» для электронных платежей.
* **Последствия при нарушении:** При падении сквозного SLI ниже 99.0% система автоматически переводит интерфейсы оформления заказов в режим «Оплата наличными при получении (COD)», предотвращая блокировку продаж. СТО инициирует эскалацию на сторону техподдержки провайдера-партнера.
