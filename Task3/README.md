# Часть 3. Нефункциональные требования, контракты SLO и стратегия доступности

## Общие сведения
Раздел переводит бизнес-требования к надежности на измеримый инженерный язык. Документы фиксируют финансово обоснованные лимиты доступности (SLA 99.9%) и определяют паттерны защиты монолита от пиковых нагрузок во время флеш-распродаж.

## Состав документов и файлов:
* **`nfr-registry.md`** — Реестр НФТ с экономическим расчетом стоимости «девяток» и обоснованием отказа от SLA 99.99%.
* **`slo/`** — Папка с OpenSLO-контрактами для изолированных программных компонентов: каталога (`catalog.md`), платежей (`payments.md`) и уведомлений (`notifications.md`).
* **`quality-attribute-scenarios.md`** — Сценарии атрибутов качества по методологии SEI/TOGAF (6 полей на сценарий).
* **`fmea.md`** — Анализ видов и последствия отказов. Заполненная матрица FMEA с расчетом индексов RPN и внедрением паттернов *Circuit Breaker*, *Bulkhead* и *Transactional Outbox*.
* **`adr-002-caching-strategy.md`** — Архитектурное решение №2. Стратегия многоуровневого кэширования (CDN Edge + In-Memory) с лимитами TTL.
* **`observability.md`** — Стратегия наблюдаемости по 4 золотым сигналам на базе open-source стека Prometheus + Loki + Grafana.
