# Стратегия наблюдаемости и мониторинга платформы (Observability Strategy)

Документ определяет архитектурный подход к сбору метрик, логированию и мониторингу MVP-контура платформы Africa Delivery в рамках установленных бюджетных ограничений (\$5 000 в месяц на регулярную ИТ-инфраструктуру) и специфики архитектурного стиля «Модульный монолит».

## 1. Четыре золотых сигнала (The Four Golden Signals)

Мониторинг здоровья системы и соблюдения целевых контрактов SLO/SLA реализуется на входном шлюзе (API Gateway) и транзакционном ядре посредством отслеживания четырех ключевых метрик Google SRE:

1. **Ошибки (Errors):**
   * *Метрика:* Процент неуспешных HTTP-ответов серии 5xx (ошибки бэкенда) относительно общего объема входящего трафика.
   * *Инженерная ценность:* Мгновенная фиксация деградации кода монолита или отказов внешних API (Paystack, Sendbox) до того, как простой начнет генерировать финансовые убытки.
2. **Задержка (Latency):**
   * *Метрика:* Время обработки входящих запросов, измеряемое через перцентиль **P99** (99% пользователей получают ответ быстрее целевого времени).
   * *Инженерная ценность:* Контроль выполнения требования маркетинга («меньше двух секунд до первого товара»). Рост Latency P99 > 1.5 сек для каталога сигнализирует о перегрузке СУБД PostgreSQL.
3. **Трафик (Traffic / Нагрузка):**
   * *Метрика:* Количество запросов в секунду (RPS — Requests Per Second) к API Gateway и текстовому USSD-шлюзу.
   * *Инженерная ценность:* Оценка интенсивности входящего спроса. Позволяет отслеживать пики нагрузок в моменты старта флеш-распродаж (целевой лимит — до 10 000 конкурентных сессий).
4. **Насыщенность (Saturation):**
   * *Метрика:* Степень утилизации ресурсов сервера (CPU, RAM), а также процент заполнения пула транзакционных соединений СУБД (PostgreSQL Connection Pool Saturation).
   * *Инженерная ценность:* Предотвращение падения монолита из-за нехватки памяти (Out-of-Memory). Алерты по насыщенности пула соединений позволяют вовремя активировать паттерн Bulkhead для изоляции «тяжелых» модулей.

## 2. Архитектурный компромисс и оптимизация стека (Buy-стратегия)

В целях соблюдения лимита CFO (\$5 000/мес) принято решение отказаться от тяжелых коммерческих APM-систем и распределенной трассировки (Distributed Tracing / Jaeger) на этапе MVP.

* **Отказ от распределенного трейсинга:** Так как система развернута в виде единого Модульного монолита, в ней отсутствуют сетевые вызовы между 50 микросервисами, которые требовали бы Jaeger. Сквозной путь запроса отслеживается внутри единого лог-файла приложения, а медленные запросы к данным локализуются штатными средствами логирования СУБД PostgreSQL (медленные логи). Это экономит до 15% вычислительной мощности серверов.
* **Использование Open Source стека:** Архитектурным стандартом мониторинга утверждается легковесная связка **Prometheus + Loki + Grafana**.

## 3. Спецификация технологического стека наблюдаемости

| Слой мониторинга | Технологический стек | Метод сбора и оптимизации | Драйвер стоимости и утилизации в TCO |
| :--- | :--- | :--- | :--- |
| **Сбор и хранение метрик** | **Prometheus** (Open Source) | Приложение на Go самостоятельно рассчитывает метрики 4 золотых сигналов и отдает их в текстовом формате по эндпоинту `/metrics` (Pull-модель). Prometheus собирает данные раз в 30 секунд. | Минимальное потребление CPU. Хранение метрик ограничивается глубиной (Retention) в 14 дней для экономии дисков. |
| **Визуализация и алертинг** | **Grafana** (Open Source) | Построение единого дашборда для ИТ-команды (техническое здоровье монолита) и Инвестора (бизнес-метрики: регистрации, заказы, выручка с обновлением раз в минуту). | Бесплатное лицензирование. Развертывается в виде легковесного контейнера. |
| **Сбор и агрегация логов** | **Grafana Loki** (Open Source) | Монолит пишет структурированные логи строго в формате JSON в стандартный поток вывода (stdout). Loki собирает логи и передает их в сжатом виде в облачное объектное хранилище AWS S3. | **Pay-as-you-go тарификация**. Использование AWS S3 для хранения логов обходится в десятки раз дешевле традиционных баз данных (Elasticsearch). |
| **Мониторинг внешних интеграций** | Локальные адаптеры API в коде Go | Каждый вызов внешних API (Paystack, Sendbox, WhatsApp) оборачивается в метрики Prometheus, отслеживающие количество ошибок 5xx со стороны партнеров и время их ответа. | Позволяет мгновенно локализовать сбой на стороне внешнего провайдера и автоматически переключить интерфейсы в защищенный режим (Circuit Breaker / Failover). |
